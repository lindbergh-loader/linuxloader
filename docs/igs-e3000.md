# IGS E3000 dumps

How Speed Driver 4's dump (`e3000_speeddriver4.chd`, 2026-11-12) became a game
directory with a decrypted board firmware, and how to do the same for another
E3000 dump: `tools/igs-e3000-extract.py` for the disk,
`tools/igs036-firmware.py` for the firmware.

Background reading: Gorgias's IGS arcade notes (gorgias.me, "igs-arcade-re"
1 to 4) cover the E2000 generation (SHFS 2.2, ROFS v1, the killdisk loader);
the E3000 is the next one ("introduces encryption"). Its toolkits on GitHub
are gone. MAME's `src/mame/igs/igs036crypt.cpp` has the IGS036 ROM scheme.

## The disk

```sh
tools/igs-e3000-extract.py games/e3000_speeddriver4.chd "games/Speed Driver 4" games/work
```

The work directory gets the raw disk (8 GB for Speed Driver 4) and is
emptied afterwards. The tool needs `chdman` (for a CHD), `unsquashfs` with
LZO, `debugfs` and `upx`; no root.

| Partition | Content |
| --- | --- |
| hda1 | ext2, its metadata scrambled behind a "Game Image v2" header, its data blocks plain: the kernels LILO boots |
| hda2 | the root, igs_rofs v2, encrypted (not needed) |
| hda3 | the game's data, IGS_SHFS: squashfs 4.0 (LZO) behind a 0xac-byte IGS superblock (`/SD4/data`) |
| hda4 | ext3, `/SD4/readwrite`: the executable, its libraries, settings, logs |

The IGS superblock is the magic `d4aa2682`, the IGS banner to 0x40, then the
squashfs fields in another order (the table is in the tool). Rewritten as a
standard superblock, the partition is plain squashfs: no data is encrypted.

The output is `data/` and `game/`, and `readwrite`, a link to `game` (the
cabinet's name for it, which some data uses); the game runs from `game/`
with `../data`.
`game/go_product` names the executable and its arguments (Speed Driver 4:
`./olympus 24636 9344 2016`). olympus is UPX 3.08-packed; unpacked, it keeps
its symbols and debug info. The packed file stays as `olympus.upx`.

The kernel, if needed: hda1's kernel file starts at block 0x1001 (1 KiB
blocks) and follows ext2's indirect blocks (0x100d, then the
double-indirect 0x110e), which are plain. The gzip inside is Linux 2.6.32.8
("James Kernel") with `igs_rofs` and `IGS_SHFS`. Without root, read it with
the block pointers rather than a mount.

## The board firmware

Speed Driver 3 and Speed Rider 2 load their IGS036 firmware from a file
(`P2A_LoaderAdv_iLoadData("../sd3.bin")`). Speed Driver 4 embeds it in the
executable (`P2A_LoaderAdv_iLoadDataPointer`, 0x90000 bytes at 0x09020600,
from `Real36::loadBinTo36`). Either way it is a 64 KiB header and the
512 KiB ROM:

- The header: the game decrypts it with the FPGA (`P2A_Loader_iDDecryptData`,
  ioctls 0x660d / 0x40106606 / 0x660e / 0x80106605 on `/dev/pccard0`) and
  reads the ROM's CRC offsets from it.
- The ROM is sent as it is (`P2A_Comm_iLowSendData`). It reaches the IGS036
  through the FPGA's cipher, and the IGS036 decrypts it with its own scheme.
  The game checks each 64 KiB block's CRC against the board's.

So `rom = igs036_decrypt(fpga(body))`, with two unknowns:

- the FPGA cipher's 16-byte mask (the bit permutation is `cipherPerm` in
  `igsA36.c`, used in the "encrypt" direction);
- the IGS036 game key, 256 bytes (MAME's scheme: an address-driven rotation
  and bitswap of each 16-bit word, then key bits XORed in by address
  triggers).

```sh
tools/igs036-firmware.py --elf "games/Speed Driver 4/game/olympus" \
    --ref "games/Speed Rider 2/game/roms/sr2_eprom_final.bin" \
    --ref "games/Speed Driver 3/game/roms/sd3_eprom.bin" \
    "games/Speed Driver 4/game/roms/sd4_eprom.bin"
```

`--image file` takes a firmware file (`sd3.bin` style) instead of an ELF.
`--at`/`--size` override the address and size found from
`Real36::loadBinTo36`. Give every decrypted IGS036 ROM at hand as `--ref`
(Speed Driver 4's own, once done, helps the next one).

How it works:

1. **The fill.** The ROM's unused tail is a 256-byte pattern repeated to
   the end. Its ciphertext repeats, and everything is linear over GF(2).
   The repeated blocks give a system in the pattern (2048 bits), the FPGA
   mask (128) and the key (2048), solved by elimination. On Speed Driver 4
   it fixes the mask and all but 828 key bits.
2. **Known plaintext.** Words the fill never reaches: code and strings shared
   with the reference ROMs (the "E-3000 ASIC2PC" sample code, `A2P_Comm_*`,
   libc), found at any offset from 8-byte anchors, vote the remaining bits.
   A byte-bigram model trained on the references settles the rest first.
3. **The fill again.** With the pattern known, every fill word re-votes the
   bits it reaches.
4. **The check.** The fill hides a 16-byte magic and the ROM's hash (MAME's
   `calculate_hash`, two shifts searched). A match means every word is
   right. The tool exits 1 without one.

Speed Driver 4:

| | |
| --- | --- |
| FPGA mask | `b9a3cfb27bd1dfc6c1a856dcbb0d11a7` |
| fill | from 0x8ca0 |
| magic, hash | at 0xa15c, `fa25b3f0`, shifts 6 and 5 |
| ROM | `game/roms/sd4_eprom.bin`, md5 `70fd238a5228dbf9ee051692f2b563d4` |

If the hash does not match: run again with more references, or look at
`grep -a` strings of the output for garbled text. Garbled text means key bytes
(the low byte of the word address) the fill and the references missed.
